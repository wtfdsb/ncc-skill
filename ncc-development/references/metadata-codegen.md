# 元数据、代码生成与模板

## BMF 设计

- 主键通常使用 `UFID/CHAR(20)`，并保持 VO、DDL、模板一致。
- 业务参照使用 REF；枚举先创建枚举类型，再把属性类型绑定到该枚举。
- 日期与日期时间按业务精度选择 `UFDate` 或 `UFDateTime`。
- 数量使用 `UFDouble/NUMBER(p,s)`，明确是否必填、精度和上下界。
- 快照字段用普通 String/数值保存，参照主键另存；不要用显示值替代主键。
- 标准业务接口字段可能带来非空约束，例如交易类型主键。生成后必须审查 DDL。

## 三处必须一致

| 层 | 核对项 |
|---|---|
| BMF | 属性名、Java 类型、数据库字段、参照/枚举 |
| 数据库 | 列名、类型、长度、默认值、非空、主键 |
| VO | 常量、成员、getter/setter、表名与主键元数据 |

页面不显示 REF 时，再检查页面模板中真正放入的是主键字段还是快照字段，以及前端是否把 `itemtype/refcode` 覆盖为普通输入框。

## 生成与再生成

1. 生成前保存或记录用户修改。
2. 检查业务流/审批流插件要求的元数据类型。
3. 检查生成 SQL 是否重复注册主键、应用或菜单。
4. 不直接全量覆盖已有前后端；对比后选择性合并。
5. 生成后验证 Java、XML、SQL、模板编码。

## 常见错误

- BMF `property` 语法错误：检查上一属性的闭合、分号及 XML/模型语法。
- 生成器空指针：检查属性数据库映射、列名、类型和枚举绑定是否完整。
- `ORA-01400`：对照 DDL 非空列与新增默认值/交易类型上下文，不要只改前端必填提示。
- 页面仍是旧类型：元数据发布不等于模板更新；检查页面模板缓存和运行时 `initMeta`。
